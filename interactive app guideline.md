make the interactive layer a core delivery format, not an optional add-on.

Your current delivery modes become:

Read as Magazine — visual, comfortable, emotional/educational consumption.
Read — conventional structured guide.
PDF — downloadable/offline/reference version.
Image — cards, quick-reference visuals, shareable assets.
Read Aloud — accessibility + hands-free consumption.
Interactive App — DO / DECIDE / TRACK / RESCUE / COMMUNICATE.

The key is: don't turn the PDF into an app. The app should perform the parts that are inherently better when software handles them.

What the interactive app should do

For the Cord Care product, for example, the app could have:

1. TODAY

The mother opens it and immediately sees:

Today's day since birth
Today's 30-second routine
☐ Hands washed
☐ Cleaned if soiled
☐ Nappy folded below stump
☐ 30-second check completed
Everything normal? YES / SOMETHING CHANGED

Completion automatically updates the tracker.

2. CHECK

Instead of making her reread the guide:

What are you seeing right now?

She answers one question at a time.

Baby unwell? → Skin changed? → Stump changed? → Substance applied?

The app branches accordingly and produces the appropriate next action.

That's substantially better than a static PDF decision tree.

3. TRACK

The app automatically maintains:

Daily care history
Symptoms/observations
Substance incidents
Photos
Separation date
Notes
Missed days
Milestones

Then it can generate a doctor-ready timeline if needed.

That's a genuine software advantage.

4. RESCUE

A permanent button:

🚨 SOMETHING LOOKS WRONG

Tap it → immediate triage flow.

No searching through 40 pages.

The user gets the relevant action pathway and emergency information.

For medical products, this area would require particularly strict clinical review before publishing.

5. FAMILY

This is where your Script Pack becomes interactive.

Instead of searching for Script #4:

What happened?

Grandma wants to apply something
Someone already applied something
Husband isn't backing me
Family says "we've always done it this way"
New helper is taking over

Tap → get the exact script → Copy / Share / Read aloud.

That's a very strong use of the app.

The app should also remember the customer's state

This is where it becomes much more powerful than a collection of PDFs.

For example:

Baby: Day 6

→ today's routine incomplete
→ yesterday substance incident
→ no red flags
→ separation hasn't happened

The platform knows the customer's current state.

So tomorrow the experience isn't:

"Open the product again."

It's:

"You're on Day 7. Here's what matters today."

That connects directly to the Customer Journey Graph we've already designed.

And this should become a reusable platform component

We shouldn't build a bespoke app for every product.

Build a Transformation Interactive Engine with reusable primitives:

Checklist
Tracker
DecisionTree
Timer
DailyPlan
Progress
State
PhotoLog
ScriptCard
RescueFlow
Reflection
Milestone
ResourceCard
Share
Export

Then each product's Product Schema declares which components it needs.

So one product might require:

DailyPlan + Checklist + Tracker + DecisionTree

Another:

Tracker + DecisionTree + ScriptCard + RescueFlow

Another:

Checklist + Progress + Reflection + Milestones

The Asset Engine chooses the components based on the transformation, rather than us deciding "every product gets an app."

Most important principle

The interactive layer should answer:

"What does the customer need to DO right now?"

The magazine/PDF answers:

"What does the customer need to UNDERSTAND?"

The image/card answers:

"What does she need to REMEMBER quickly?"

Read-aloud answers:

"What does she need to CONSUME hands-free?"

And the interactive app answers:

"What does she need to DO, DECIDE, TRACK, or RESCUE?"

That is the right evolution of the Transformation Engine. It also makes the products considerably harder to commoditize than AI-generated PDFs.
